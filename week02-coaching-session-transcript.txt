Coach: Excellent explanation! Your reasoning about 1NF and data consistency for categories

I can see your junction table service_project_category in src/setup.sql uses a composite
primary key (PRIMARY KEY (service_project_id, category_id)). Can you explain in your own
words why you chose a composite primary key for that table, rather than giving it its own

Fernando: To be honest. It was an idea that AI gave me. I'm not sure but I think the

Coach: I really appreciate that honesty, Fernando — that takes confidence, and it's exactly
the kind of thing that helps us learn! And here's the great news: your instinct is correct.
That's precisely the reason.

A composite primary key on (service_project_id, category_id) means the database itself will
reject any attempt to insert the same project+category pair twice. The combination of both
columns must be unique — so "Spring Planting Day + Food Security" can only ever appear once
in that table, enforced at the database level, not just in application code.

Now, let's look at how you actually query that data. Can you walk me through one of the SQL
queries you wrote inside one of your model files — what does it select, and why did you
write it that way?

Fernando: (from src/models/projects.js)

  const query = `
    SELECT p.service_project_id, p.organization_id, p.title, p.description,
           p.location, p.project_date, o.name AS organization_name
    FROM public.service_project p
    JOIN public.organization o ON p.organization_id = o.organization_id;
  `;

In this query we are selecting data from the projects table (service_project), specifically
the project id, organization id, title, description, location and date. We are also taking
advantage of the organization_id foreign key to do an inner join with the organization table,
and from that join we get the organization name.

I decided to avoid selecting all (*) because it is considered bad practice, and an inner join
because I only needed data from the organizations table having a related project.

[TOPIC 2: Server-Side Data Access Logic (Node.js)]

Coach: That's a really solid answer. Avoiding SELECT * and consciously choosing INNER JOIN
over LEFT JOIN based on your data needs — that's exactly the kind of intentional thinking
good developers practice.

Now let's move up one level, from the SQL itself to the Node.js code that executes it.
There should be a JavaScript function that actually runs that query against the database.
Can you show me that function and describe what it does — specifically, how does it send
the query to PostgreSQL and what does it return?

Fernando: (from src/models/projects.js and src/models/db.js)

  const getAllProjects = async () => {
    const query = `
      SELECT p.service_project_id, p.organization_id, p.title, p.description,
             p.location, p.project_date, o.name AS organization_name
      FROM public.service_project p
      JOIN public.organization o ON p.organization_id = o.organization_id;
    `;
    const result = await db.query(query);
    return result.rows;
  };

The function getAllProjects is an asynchronous function that takes no arguments. It needs
to be async because it makes use of the "db.query" method, which is the method that takes
our query and uses it to make a request to the database through the connection pool.
The connection pool is the way we are using to connect to our database. It is used via the
"Pool" class that we import from the "pg" library. For development environment, we wrap the
pool call into another method that provides logging for debugging purposes, and for
production the query is done directly through the native pool method.

That brings us to the last topic: the EJS template itself. You mentioned the data "replaces

In those code examples the syntax are different but they essentially do the same — they
run JS code inside them. The difference is that the one with the equals sign will display

---

Coach: Spot on! The distinction between <%= %> (output) and <% %> (logic only) is the
core of how EJS works, and you've got it exactly right.

There's one more tag worth noting in your own template — look at line 1 of
src/views/projects.ejs:

  <%- include('partials/header') %>

Notice the "-" instead of "=". Can you take a guess at what you think the difference
might be between <%- and <%=?

Fernando: Yes, the difference between them is that the "-" means don't escape HTML and
print it as it is. And the "=" will escape HTML characters, meaning HTML will be converted
to a string on the page. We never want to use the "-" to render content that comes from
user input because it is unsafe.

---

Coach: That is a fantastic answer, Fernando — and the security awareness at the end is
exactly right. Using <%- on user-generated content would open the door to Cross-Site
Scripting (XSS) attacks, which is one of the OWASP Top 10 vulnerabilities. The fact that
you know that shows real maturity as a developer.
